# TodoList 프로젝트 — 개요 / 공통

> 목적: 풀스택 기술 스택 전체 흐름 경험 (특히 AWS 배포 + CI/CD 파이프라인)
> 원칙: 기능은 최소로, 연결은 제대로
> 인프라 방향: 회사(deepez) 프로젝트 구조와 최대한 유사하게 구성

상세 내용은 다음 문서로 분리되어 있음:
- `01_프론트엔드.md`
- `02_백엔드.md`
- `03_인프라.md`

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 서비스명 | TodoList |
| 목적 | 프론트~인프라 전체 기술 스택 경험, 특히 ECS/Docker 기반 배포 + CI/CD 숙달 |
| 개발 방식 | Cursor AI 활용, 모노레포 구조 |
| 배포 전략 | GitHub Actions → Docker 이미지 빌드 → ECR push → ECS 배포 |
| 학습자 배경 | 프론트엔드 주니어 개발자, 백엔드/인프라는 학습 단계 |

---

## 2. 기술 스택 요약

| 영역 | 핵심 스택 |
|------|-----------|
| Frontend | Next.js 14 (App Router), TypeScript, TipTap, Tailwind, RTK/RTK Query, Docker → ECS |
| Backend | Spring Boot 3.x, Java 17, JPA, JWT+OAuth2, Gradle, Docker → ECS |
| Database | PostgreSQL (로컬 → AWS RDS) |
| Infra | ECR, ECS(Fargate), RDS, S3, CloudFront, IAM, ALB, Terraform |

세부 내용은 각 영역 문서 참고.

---

## 3. 전체 인프라 아키텍처

```
[사용자]
   │
   ├── 프론트 접속
   │     └── CloudFront → ECS (Fargate, Next.js 컨테이너)
   │
   ├── API 요청
   │     └── ALB → ECS (Fargate, Spring Boot 컨테이너)
   │                  └── RDS (PostgreSQL)
   │
   └── 이미지 업로드/조회
         └── 업로드: 프론트 → S3 직접 (Presigned URL)
         └── 조회: CloudFront → S3 (OAC)

[GitHub main 머지]
   ├── GitHub Actions → 프론트 Docker 이미지 빌드 → ECR push → ECS 서비스 업데이트
   └── GitHub Actions → 백엔드 Docker 이미지 빌드 → ECR push → ECS 서비스 업데이트
```

> EC2, Elastic Beanstalk, Amplify는 사용하지 않음 (커리큘럼 기본안에서 회사 구조에 맞춰 변경)

## 5. 공통 보안 원칙

- JWT secret, DB password, OAuth client secret 등 모든 민감 정보는 환경변수(.env) 또는 ECS Task Definition의 환경변수/Secrets Manager로 관리
- CORS 설정: 프론트 도메인만 허용
- HTTPS 강제 (CloudFront, ALB 모두 HTTPS 설정)
- IAM 정책: 모든 서비스 계정/Task Role에 필요한 권한만 최소 부여 (최소 권한 원칙)

영역별 보안 세부사항은 각 문서 참고.

## 6. 전체 개발 순서 (권장)

> ⚡ 방침: 남은 3~6단계는 **하루 안에 완주**하는 것을 목표로, 세부 네트워크 설계를 생략하고 AWS 기본값/마법사 권장 설정을 그대로 사용. 상세는 `03_인프라.md` §7 참고.

```
1단계: 인증 + 핵심 기능 — ✅ 완료
  └── Google OAuth2 + JWT 로그인 구현
  └── 투두 CRUD API
  └── TipTap 에디터 적용 (JSON 본문 저장)

2단계: 이미지 업로드 (S3, 로컬 환경에서 검증) — ✅ 완료
  └── 상세: 03_인프라.md §S3/CloudFront, 02_백엔드.md §파일 API, 01_프론트엔드.md §이미지 업로드

3단계: DB 인프라 이관 ← 오늘 목표
  └── RDS 생성 (프리티어, 기본 VPC, 퍼블릭 액세스 허용 — 보안그룹 세밀 설정 생략)
  └── 로컬 DB → RDS로 스키마 이관

4단계: 컨테이너화 + ECS 배포 ← 오늘 목표
  └── 프론트/백엔드 Dockerfile (Cursor에게 표준 멀티스테이지 빌드로 요청)
  └── ECR 리포지토리 생성 (기본값)
  └── ECS 클러스터/서비스 생성 — Fargate, 마법사 안에서 ALB까지 함께 생성
  └── (네트워크는 전부 기본 VPC/마법사 자동 설정 사용)

5단계: CDN + 도메인 (시간 되면, 아니면 다음으로 미룸)
  └── CloudFront에 프론트(ECS/ALB) 연결
  └── 시간 부족 시: ALB 도메인으로 직접 접속하는 것으로 1차 완료 처리

6단계: CI/CD 세팅 ← 오늘 목표 (최소 버전)
  └── GitHub Actions: main push 시 Docker build → ECR push → ECS 서비스 업데이트
  └── path filter, Terraform 코드화는 시간 부족 시 다음으로 미룸

7단계: 최종 확인
  └── 전체 흐름 테스트 (로그인 → 투두 작성 → 이미지 업로드 → 배포 반영 확인)
```

**오늘(하루) 우선순위 (시간 부족 시 이 순서로 줄이기)**:
1. RDS 연결 + ECS 백엔드 배포 + ALB로 API 호출 확인 (최우선, 반드시 완료)
2. ECS 프론트 배포
3. GitHub Actions 자동 배포 1회 성공
4. CloudFront(프론트), path filter 세분화, Terraform — 다음으로 미뤄도 무방

## 7. 전체 변경 이력 (공통/구조적 변경만)

| 시점 | 변경 내용 |
|------|-----------|

| 수정 | 회사(deepez) 프로젝트 구조에 맞춰 **ECS + Docker + ECR** 기반으로 전면 변경 |
| 수정 | 카카오 로그인 제거 (학습 목표와 무관, 스코프 정리) |

| 진행 | S3 + CloudFront 구축 및 E2E 검증 완료. AWS 계정 MFA 문제로 신규 계정 재생성 |
| 구조 변경 | 기획서를 영역별로 분리: 00_개요 / 01_프론트엔드 / 02_백엔드 / 03_인프라 |

영역별 상세 변경 이력은 각 문서 하단 참고.
