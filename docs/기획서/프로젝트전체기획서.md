# TodoList 프로젝트 기획서

> 목적: 풀스택 기술 스택 전체 흐름 경험
> 원칙: 기능은 최소로, 연결은 제대로

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 서비스명 | TodoList |
| 목적 | 프론트~인프라 전체 기술 스택 경험 |
| 개발 방식 | Cursor AI 활용, 모노레포 구조 |
| 배포 전략 | GitHub Actions CI/CD (master 브랜치 자동 배포) |

---

## 2. 기술 스택

### Frontend
| 항목 | 선택 | 이유 |
|------|------|------|
| 프레임워크 | Next.js 14 (App Router) | 파일 기반 라우팅, SSR 경험 가능 |
| 언어 | TypeScript | 타입 안전성, 실무 표준 |
| 에디터 | TipTap | 리치 텍스트 에디터, 이미지 첨부 연동 |
| 스타일 | Tailwind CSS | 빠른 UI 구성 |
| 상태관리 | RTK, RTK Query | 전역상태관리, API 결과 상태 관리 |
| 배포 | AWS Amplify | GitHub 연동 자동 배포 |

### Backend
| 항목 | 선택 | 이유 |
|------|------|------|
| 프레임워크 | Spring Boot 3.x | Java 기반 표준 백엔드 |
| 언어 | Java 17 | LTS 버전, 안정적 |
| ORM | JPA (Hibernate) | DB 접근 추상화 |
| 인증 | JWT + OAuth2 | 소셜 로그인 + 자체 토큰 관리 |
| 빌드 | Gradle | 의존성 관리 |
| 배포 | AWS Elastic Beanstalk | EC2 + 로드밸런서 자동 관리 |

### Database
| 항목 | 선택 | 이유 |
|------|------|------|
| DB | PostgreSQL | 안정적, AWS RDS 완전 지원 |
| DB명 | TodoListDB | - |
| 스키마 | todolist_db | - |
| 호스팅 | AWS RDS | 관리형 DB, 백업 자동화 |

### 인증
| 항목 | 선택 |
|------|------|
| 방식 | JWT (Access Token 30분 + Refresh Token 7일) |
| 소셜 로그인 | Google OAuth2 |

### 인프라 (AWS)
| 서비스 | 용도 |
|--------|------|
| EC2 | Spring Boot 서버 실행 (Beanstalk이 관리) |
| Elastic Beanstalk | 백엔드 배포 자동화 및 인프라 관리 |
| RDS | PostgreSQL DB 호스팅 |
| S3 | TipTap 에디터 이미지 저장소 |
| CloudFront | S3 이미지 CDN (빠른 이미지 로딩) |
| Amplify | Next.js 프론트 배포 + GitHub 연동 |
| IAM | AWS 권한 관리 |

### IaC
| 항목 | 선택 |
|------|------|
| 도구 | Terraform |
| 관리 대상 | S3, RDS, Beanstalk, CloudFront, IAM |

## 3. 서비스 기능 정의

### 3-1. 인증
- 구글 소셜 로그인
- 카카오 소셜 로그인
- JWT Access Token / Refresh Token 발급 및 재발급
- 로그아웃 (Refresh Token 무효화)

### 3-2. 투두 CRUD
- 투두 생성 (제목 + TipTap 에디터 본문)
- 투두 목록 조회 (내 투두만)
- 투두 상세 조회
- 투두 수정
- 투두 삭제
- 완료 여부 토글 (완료 / 미완료)

### 3-3. 이미지 업로드
- TipTap 에디터 내 이미지 첨부
- 이미지 → S3 업로드 → CloudFront URL 반환 → 에디터에 표시

## 4. DB 설계

### 테이블 구조

#### users (유저)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGSERIAL PK | 유저 고유 ID |
| email | VARCHAR(255) UNIQUE NOT NULL | 이메일 (소셜 로그인 기준) |
| nickname | VARCHAR(100) NOT NULL | 닉네임 |
| provider | VARCHAR(20) NOT NULL | 소셜 제공자 (google / kakao) |
| provider_id | VARCHAR(255) NOT NULL | 소셜 제공자 고유 ID |
| refresh_token | TEXT | Refresh Token 저장 |
| created_at | TIMESTAMP DEFAULT NOW() | 생성일 |
| updated_at | TIMESTAMP DEFAULT NOW() | 수정일 |

#### todos (투두)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | BIGSERIAL PK | 투두 고유 ID |
| user_id | BIGINT FK → users.id | 작성자 |
| title | VARCHAR(255) NOT NULL | 제목 |
| content | TEXT | TipTap JSON 본문 |
| is_completed | BOOLEAN DEFAULT FALSE | 완료 여부 |
| created_at | TIMESTAMP DEFAULT NOW() | 생성일 |
| updated_at | TIMESTAMP DEFAULT NOW() | 수정일 |

## 5. API 설계

### 인증 API
| Method | URL | 설명 |
|--------|-----|------|
| GET | /api/auth/google | 구글 로그인 시작 |
| GET | /api/auth/kakao | 카카오 로그인 시작 |
| POST | /api/auth/refresh | Access Token 재발급 |
| POST | /api/auth/logout | 로그아웃 |

### 유저 API
| Method | URL | 설명 |
|--------|-----|------|
| GET | /api/users/me | 내 정보 조회 |

### 투두 API
| Method | URL | 설명 |
|--------|-----|------|
| GET | /api/todos | 내 투두 목록 조회 |
| POST | /api/todos | 투두 생성 |
| GET | /api/todos/{id} | 투두 상세 조회 |
| PUT | /api/todos/{id} | 투두 수정 |
| DELETE | /api/todos/{id} | 투두 삭제 |
| PATCH | /api/todos/{id}/complete | 완료 여부 토글 |

### 파일 API
| Method | URL | 설명 |
|--------|-----|------|
| POST | /api/files/upload | 이미지 S3 업로드 → CloudFront URL 반환 |

## 7. 인프라 아키텍처

```
[사용자]
   │
   ├── 프론트 접속
   │     └── CloudFront (없음, Amplify 직접) → AWS Amplify → Next.js
   │
   ├── API 요청
   │     └── Elastic Beanstalk → EC2 (Spring Boot)
   │                               └── RDS (PostgreSQL)
   │
   └── 이미지 요청
         └── CloudFront → S3 (이미지 저장소)

[GitHub master 머지]
   ├── GitHub Actions → Amplify 빌드 트리거 (프론트)
   └── GitHub Actions → Beanstalk 배포 (백엔드)
```

---

## 8. CI/CD 전략

### 프론트엔드
- Amplify와 GitHub 레포 연동
- master 브랜치 머지 시 Amplify 자동 빌드 및 배포

### 백엔드
- GitHub Actions에서 Gradle 빌드 → JAR 파일 생성
- JAR 파일을 Elastic Beanstalk에 배포

---

## 9. 보안 고려사항

- JWT secret, DB password, OAuth client secret 등 모든 민감 정보는 환경변수로 관리
- CORS 설정: 프론트 도메인만 허용
- HTTPS 강제 (Amplify, Beanstalk 모두 HTTPS 설정)
- S3 버킷 퍼블릭 직접 접근 차단 → CloudFront로만 접근
- SQL Injection 방지: JPA 사용, 네이티브 쿼리 최소화
- XSS 방지: JWT를 httpOnly 쿠키로 관리

## 10. 개발 순서 (권장)

```
1단계: 인프라 기반 세팅
  └── Terraform으로 RDS, S3, CloudFront 생성
  └── Elastic Beanstalk 환경 생성
  └── Amplify + GitHub 연동

2단계: DB 세팅
  └── RDS 접속 후 init.sql 실행

3단계: 백엔드 개발
  └── 프로젝트 세팅 (Spring Boot, JPA, Security)
  └── JWT + OAuth2 인증 구현 (Google, Kakao)
  └── 투두 CRUD API
  └── S3 이미지 업로드 API

4단계: 프론트엔드 개발
  └── 프로젝트 세팅 (Next.js, Tailwind, Zustand)
  └── 소셜 로그인 화면
  └── 투두 목록 / 상세 / 작성 화면
  └── TipTap 에디터 + 이미지 업로드 연동

5단계: CI/CD 세팅
  └── GitHub Actions 워크플로우 작성
  └── 배포 테스트

6단계: 최종 확인
  └── HTTPS, CORS, 환경변수 점검
  └── 전체 흐름 테스트
```
